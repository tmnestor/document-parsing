# DSL Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lift the layout DSL and its supporting rendering machinery out of
`Synthetic_Doc_Generation` into this repo, stripped of every extraction-specific
dependency, until `pipeline generate` renders a page image from YAML.

**Architecture:** A near-verbatim port. The predecessor's package is already
named `generators/`, so intra-package imports (`from generators.common import
...`) survive unchanged and the port is dominated by *deletions*, not rewrites.
Two couplings must be severed: `generators.exporters.geometry.BoxRecorder`
(imported by `common.py`, `context.py`, `engine.py`, `primitives_table.py`,
`bank_statement.py`) and `payment_block.load_link_index` (imported by
`field_providers.py`). Everything else crosses as-is.

**Tech Stack:** Python 3.12, Pillow, PyYAML, typer, rich, Faker. pytest, ruff,
mypy. Conda env `docparse`.

**Spec:** `docs/superpowers/specs/2026-08-17-document-parsing-corpus-design.md`

**Source repo:** `/Users/tod/Desktop/Synthetic_Doc_Generation` (referred to below
as `$PRED`). Read-only — never write to it.

## Scope

This plan delivers **rendering only**. It ends with a repo that validates ground
truth and renders correct page images. It deliberately does **not** implement:

- `TranscriptRecorder` and draw-time event capture (spec §4.1–4.2)
- The serialiser and `config/serialisation.yml` (spec §4.3–4.4)
- The `serialise`, `export` and `preview` commands (spec §6)
- The coverage invariant (spec §8.2)

Those are the next plan. This one exists because none of them can be built
against a renderer that does not yet run here.

## Global Constraints

Every task's requirements implicitly include these. Values copied verbatim from
the spec (§10.1, §10.2) and the repo's CLAUDE.md.

- Python 3.12. Use `X | Y`, not `Union[X, Y]`. No `from __future__ import annotations`.
- Never use `TYPE_CHECKING` guards for types used in runtime signatures.
- Line length 108.
- All paths are `pathlib.Path`.
- Google-style docstrings.
- `ruff check --fix --ignore ARG001,ARG002,F841` and `ruff format .` clean.
- `mypy . --ignore-missing-imports` clean.
- Exceptions raised inside `except` blocks use `from err` or `from None` (B904).
- Dependencies are exactly: `Pillow`, `PyYAML`, `typer`, `rich`, `Faker`. Adding
  `numpy` or `opencv` is a plan violation — they left with the degradation module.
- Conda env is `docparse`, not `du`. Run tooling as `conda run -n docparse <cmd>`.
- YAML is the single source of truth. No config value gets a Python default. A
  missing key fails fast; it never falls back.
- Every config validation error carries four elements: what is wrong, absolute
  file path plus dotted key path, a concrete valid YAML example, and a one-line
  remediation.
- `tests/` and `CLAUDE.md` are gitignored (spec §8.3, §10, both reversed
  2026-08-17). Tests are still written and run before every commit; they are just
  not committed. Commit commands below therefore stage source and config only.

**The recorder excision, precisely.** Everywhere the source has a
`recorder: BoxRecorder | None = None` parameter or a `ctx.recorder` access, the
parameter and its call-site argument are deleted, along with the `field=`
argument that names the box. This is safe to delete rather than preserve because
the next plan re-plumbs the identical call sites to carry `transcript` and `seq`
instead — spec §4.1 puts capture inside these same primitives, so they get
edited again regardless. Preserving dead extraction plumbing through the port
would mean shipping a concept the corpus does not have.
